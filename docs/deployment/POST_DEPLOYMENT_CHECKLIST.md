# Post-deployment Checklist: Gymyamjamsai

เอกสารตรวจสอบความพร้อม **หลังการนำระบบขึ้น Production (Post-deployment Checklist)** ออกแบบมาสำหรับการรันระบบผ่าน **Railway (Single-container)** เพื่อใช้ยืนยันว่าการตั้งค่าทุกจุดทำงานได้อย่างสมบูรณ์ก่อนเปิดให้ผู้ใช้งานจริงเข้าใช้ (Final Go-live)

---

## 📋 Checklist (ตารางตรวจสอบ)

| Item | How to Check (วิธีตรวจสอบ) | Expected Result (สิ่งที่คาดหวัง) | Status (สถานะ) | Notes (หมายเหตุ) |
| :--- | :--- | :--- | :---: | :--- |
| **1. Service Status** | ไปที่หน้า Railway Dashboard ดูสถานะของ App และ DB | ขึ้นแถบสีเขียว (Active) และไม่มี Error loop ตอน Start-up | [ ] | |
| **2. Domain and SSL** | พิมพ์โดเมนหลัก (เช่น `https://yourapp.railway.app`) ในเบราว์เซอร์ | ระบบใช้ `https://` อัตโนมัติ รูปกุญแจปลอดภัย ไม่ขึ้นแจ้งเตือน SSL | [ ] | |
| **3. Frontend Test** | กดรีเฟรช (F5) ที่หน้าใดหน้าหนึ่งเช่น `/login` | ระบบโหลดหน้า React ได้ ไม่ขึ้น 404 (SPA Fallback ทำงาน) | [ ] | |
| **4. Backend API Test** | เปิดบราวเซอร์ไปที่ URL `https://.../api/health` | ได้ผลลัพธ์เป็น JSON `{"status": "ok", "db": "connected"}` | [ ] | |
| **5. Database Test** | ทดลองสมัครสมาชิกใหม่ผ่านหน้าเว็บ | ข้อมูลถูกบันทึกลง DB และหน้าเว็บสลับไปหน้า Dashboard ได้ | [ ] | |
| **6. Login & Permission Test** | ล็อกอินด้วยบัญชี `admin`, `trainer`, `member` ตามลำดับ | ระบบแสดง Sidebar และเมนูต่างกันตามสิทธิ์ ไม่สามารถเข้าข้ามสิทธิ์ได้ | [ ] | |
| **7. Main Workflow Test** | ให้ Trainer สร้างคลาสเรียน และให้ Member ลองกดจอง | คลาสถูกสร้างสำเร็จ, จำนวนที่นั่งลดลง, และมีแจ้งเตือนสีเขียว | [ ] | |
| **8. Dashboard Test** | ล็อกอินด้วย Admin ไปที่หน้า Dashboard | กราฟและตัวเลขสรุปผลแสดงขึ้นมาครบถ้วน (ตัวเลขไม่เป็น NaN) | [ ] | |
| **9. Backup Test** | จำลองสั่ง Backup จาก SRE Script (หรือรอดูเช้าวันถัดไป) | ไฟล์ `.sql` ถูกสร้างขึ้นและดาวน์โหลดมาเปิดดูโครงสร้างได้ | [ ] | |
| **10. Log & Monitoring Test** | ดูแท็บ View Logs ในแพลตฟอร์ม Railway | ข้อมูล Log เป็นระเบียบ ไม่แสดง Error จากคำขอ (Request) ทั่วไป | [ ] | |
| **11. Security Check** | ดูในแท็บ Variables ของ Railway ว่าใส่คีย์ความปลอดภัยครบไหม | `JWT_SECRET`, รหัสผ่าน DB เป็นของจริงและคาดเดายาก (ไม่ใช่ .env.example) | [ ] | |
| **12. User Acceptance** | สุ่มให้ End-user หรือผู้บริหารทดลองจิ้ม 1-2 Flow ภายในระบบจริง | ผู้ใช้เห็นด้วยและไม่มีข้อขัดข้องกับความเร็ว/การใช้งาน | [ ] | |
